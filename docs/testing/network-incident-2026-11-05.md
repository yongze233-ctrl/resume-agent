# 2026-11-05 晚间服务不可用排查

以下时间均为北京时间。读取了线上容器日志、网关访问记录和持久化失败记录；没有导出用户简历或对话内容。

## 日志确认的故障

- **22:38:07**：`design_canvas_unavailable`，最后工具为 `design_resume`。画布页面在 22:36:58 开始加载，静态资源请求均返回 200，但第一次领取画布任务的请求直到 22:40:25 才出现，超过后端 70 秒等待窗口。服务器日志不足以确认浏览器初始化延迟的具体原因。
- **22:43:55**：模型请求准备阶段报 `model_unavailable`。同一时刻，TLS 连接遇到 `ENETUNREACH`，未处理的 socket error 使 Node 进程退出。
- **22:43:58–22:44:02**：前端三次连接 Agent 被拒绝，返回 500。
- **22:44:04**：Agent 自动重启并恢复监听；旧的内存画布会话失效，后续轮询返回 404。此前容器累计重启一次，不是 OOM。

这次有应用连接代码导致的后端崩溃证据，不能仅解释为模型供应商不稳定。

## 根因与修复

线上旧连接器只使用 DNS 返回的第一个地址。若第一个是服务器无法访问的 IPv6，即使还有可用 IPv4，也不会尝试。它还同步调用自定义 DNS 回调；在生产 Node 22 的 TLS 错误路径下，请求已拒绝后仍可能出现未处理的 socket error，直接结束进程。

修复保持原有域名、TLS 校验及所有 DNS 地址的安全检查：

1. DNS 回调异步执行，让连接器按正常生命周期注册错误监听。
2. 使用全部已经校验的地址，启用地址族回退。
3. 没有通过全局吞掉 `uncaughtException` 来掩盖异常，也没有关闭 TLS 校验。
